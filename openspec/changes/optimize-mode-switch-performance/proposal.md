## Why

规则代理、全局代理和全局直连的切换会同步停止内核、清理 TUN、重建配置并等待就绪，主窗口在此期间无法响应。切换失败还可能在旧配置已停止后才暴露预检错误，增加无谓断连和恢复成本。

## What Changes

- 为每次模式切换记录可关联的阶段耗时、结果和失败阶段，使 Windows 实机验收能够定位停止、TUN 清理、DNS 刷新、启动或就绪等待的瓶颈。
- 在停止当前运行内核前完成目标模式的凭据读取、上游解析、配置编译、受限写入和内核配置校验；预检失败时保持当前已应用模式和网络接管。
- 对规则代理与全局代理的切换复用受管 TUN 生命周期，并以短间隔、有上限的状态检测取代适配器删除后的固定等待；切换到直连和退出仍完成完整网络恢复与 DNS 刷新。
- 将模式切换移至后台工作任务。UI 在应用期间持续响应、展示当前阶段并禁用冲突操作；仅在新配置完全就绪后更新实际已应用模式，失败时显示错误并维持或恢复真实状态。
- 评估并预留 sing-box 路由热重载路径；只有通过 Windows 流量、DNS、回滚与异常恢复验证后才允许启用，默认仍采用已验证的受控重启回退。

## Capabilities

### New Capabilities

- `mode-switch-observability`: 提供模式切换的阶段化进度与可脱敏诊断耗时，支持性能验收和故障定位。

### Modified Capabilities

- `core-lifecycle`: 模式切换预检不得中断现有有效接管；受控重启、TUN 复用、直连恢复和失败回滚需保持网络恢复语义。
- `desktop-shell`: 耗时模式切换期间窗口和托盘必须保持可响应，并一致呈现进行中、成功或失败的实际状态。

## Impact

主要影响 `src/core/runtime.rs` 的配置准备、核心生命周期和诊断，`src/core/process.rs` 的进程/TUN 等待策略，`src/core/transaction.rs` 的事务阶段，以及 `src/ui/controller.rs`、`src/ui/mod.rs` 和托盘状态更新的异步接口。需要新增可控时钟或阶段事件测试、Windows x64 实机耗时证据、模式切换失败注入和 UI/托盘响应验证；不改变代理协议、凭据格式、规则匹配语义或全局直连的 DNS 恢复承诺。
