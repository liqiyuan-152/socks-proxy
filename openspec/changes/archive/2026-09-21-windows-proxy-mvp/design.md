## Context

项目初始化前没有任何文件、代码、Cargo 工程或测试，亦无 `.codegraph/`。需求依据见 requirements-source.md，动机见 proposal.md。本次仅产出文档；宿主是 macOS，网络相关验收必须在 Windows 10/11 x64 上进行。

## Goals / Non-Goals

**Goals:** 将纯业务配置、Windows 平台适配、内核控制与 GUI 分层；所有入口共享一个状态源；将有效配置切换、凭据隔离及可恢复网络操作作为架构约束。

**Non-Goals:** 自研代理内核、WebView/Tauri、多代理并行路由、按进程/正则规则、第四模式、后台服务、跨平台发行、远程日志上报、系统级崩溃阻断保护。首版不承诺游戏/全部 UDP 可用，不承诺任何切换下现有 SSH 永不断开。

## Decisions

### D1. Rust 桌面壳与单一控制器

采用已确认的 egui/eframe + tray-icon + muda；无需 Windows 原生控件外观。规划模块：domain（模型和校验）、routing（规则编译）、core（sing-box 适配）、platform/windows（UAC、凭据、进程、网络恢复）、storage、logs、ui。先使用单 Cargo 工程及模块边界，避免过早拆分多 crate。

GUI 和托盘只发命令并订阅快照，不直接改路由或配置；阻塞网络操作在后台执行。状态区分期望模式、已应用模式、配置修订和 Direct/Starting/Running/Reconfiguring/Stopping/Error；切换期间串行化命令，失败显示实际状态。单实例约束防止两个进程争抢 TUN。Tauri 被用户否决，自研转发内核不在范围。

### D2. 数据模型与持久化

ProxyProfile 包含 id/name/protocol/host/port/auth_enabled/credential_ref；RoutingRule 包含 id/name/enabled/target_kind/target/ports/note；AppConfig 包含 schema_version/profiles/active_profile_id/rules/last_applied_mode/preferences。凭据单独保存。ports 解析为规范化区间；IP 范围编译为等价 CIDR 集合，包含端点并限制展开规模，IPv4/IPv6 使用对应宽度算法。域名规范化大小写、尾点和国际化形式，后缀匹配要求标签边界。

采用版本化 JSON 和原子替换文件，保留最近有效配置；未知新版本拒绝导入。导入可在任意状态预览，但仅允许在已完成网络恢复的 Direct 状态提交；运行中必须由用户显式切换直连，Error 或切换中禁止提交。提交时重新校验状态与配置修订，串行锁内校验全部引用/字段并原子替换，失败保留旧配置、凭据及当前状态。导入不应用网络配置、不改变当前直连模式，也不接受备份中的自动启用模式；认证信息缺失标记待补充，以独立认证启用标记区分无认证代理和缺凭据代理。旧凭据仅在提交成功且无引用后清理，不按同名代理自动复用。运行配置与编辑草稿分开，应用成功才更新 last_applied_mode。相较直接写 sing-box JSON，此模型可以稳定 UI 语义并隔离内核版本变化。

### D3. 规则编译、DNS 与上游能力

固定经 M0 验证的 sing-box 版本，不在本规划猜测具体 JSON 字段。编译顺序：本机控制和上游端点防回环例外 → 模式策略。规则模式随后按用户启用规则代理、最终直连，不把所有私网作为前置直连；全局模式私网/链路本地/本机例外后默认代理。多规则命中结果相同；仅在内核提供可验证命中信息时映射稳定 ID，否则显示未知，不推断规则。

DNS 规划采用 sing-box 管理的解析及 FakeIP 映射，使应用连接 IP 时仍保有域名来源；启动引导解析和代理服务器解析走独立防回环路径，不能依赖尚未建立的代理。DNS 按用途固定出站：启动引导、代理服务器地址、路由判定所需真实 A/AAAA、未命中规则的直连目标解析均使用独立 direct 出站，采用接管前可用的系统/网络 DNS 上游并避开本程序 DNS 监听入口；不依赖当前代理，也不通过受接管的系统解析调用形成回环。网络变化时重新获取有效上游，不能固定使用已失效的网卡地址。已命中域名规则的目标优先把域名交由代理端解析；必须在本地取得地址时使用经当前代理传输的 DNS，上游故障不得改用直连解析。路由判定 DNS 即使在全局模式也属于明确的基础直连例外，可能向本地 DNS 暴露查询，MVP 不承诺全部 DNS 经过代理；设置说明中展示该边界。IPv4 和 IPv6 都覆盖。处理旧缓存时使用受支持的缓存刷新/提示重连，不将任意共享 IP 永久归因到某域名。应用自有 DoH/DoT 无法恢复映射时不承诺域名识别，按 IP/端口决策并说明限制。

FakeIP 只用于恢复域名，不能直接参与用户真实 IP/CIDR/范围匹配。基础例外之后，先判断域名与端口规则；未命中且存在 IP 类规则时，使用受管理解析器取得真实 A/AAAA 候选集，任一真实候选地址与端口命中则整条逻辑连接代理，否则直连。此处采用候选集任一命中语义，避免多地址重试改变出站；域名命中无需为了 IP 判断强制本地解析。全局模式的内网例外同样基于真实地址，混合公网/内网候选不整体豁免，仅全为内网时适用该例外。路由判定使用上述独立直连 DNS；仅在该 DNS 本身可用时保证上游代理故障不影响未命中域名。需要解析才能决策而解析失败时连接失败，不把未知当作未命中，也不改走代理 DNS 重新选择路径；日志记录用于决策的真实候选集，不能把 FakeIP 当作目标真实地址。M0 验证锁定内核的解析/规则接口能实现此语义；若不能，先修订方案，不默默省略 IP 规则。

HTTP CONNECT 是否允许 22 端口由上游决定；TCP 验证优先。HTTP 下应代理的 UDP 拒绝并记录，不能偷偷直连。SOCKS5 UDP 先验证上游能力，再启用相应行为。受管理 DNS 是程序基础通信，不依赖 HTTP 承载普通 UDP，可选择支持的 DNS 传输。

### D4. 内核管理、切换与网络恢复

应用使用 Windows 提权入口，每次普通启动 UAC 授权；已经提升的进程遵循 Windows 行为，不保证系统会重复弹框。取消不创建内核。使用受控路径的 sing-box.exe、隐藏控制台、校验版本及文件完整性；子进程受应用监管。

启用事务：验证模型 → 生成受保护临时配置 → 执行内核配置校验 → 保存本程序拥有的网络变更恢复记录 → 启动内核 → 验证就绪 → 提交已应用状态。运行时优先通过经验证接口切换出站，无法热切换则提示断连风险后受控重启；不依赖尚未验证的热重载能力。失败撤销新改动并恢复旧配置；恢复不成功进入 Error。

正常停止：停止发放新的 FakeIP、停止接管及内核、恢复本程序路由/DNS、调用受支持的 Windows DNS 缓存刷新接口、验证系统解析不再返回本程序 FakeIP，随后清理临时秘密并删除完成的恢复记录。系统刷新或恢复失败时保留记录并报告可重试错误。应用自身 DNS 缓存无法保证被清除：切换直连/退出前提示受影响应用可能需要重启或重新解析，不强制关闭其他应用；系统恢复完成与应用缓存提示分开呈现，不声称所有现有会话立即恢复。保留错误记录供重试，退出前呈现恢复失败。恢复采用资源所有权与修改前后值比对，不直接覆写整台机器的网络快照，以免破坏 VPN 或用户后续修改。下次启动先执行幂等残留恢复。

FakeIP 映射在兼容内核重启中通过受限的持久缓存保留并先于接管恢复，普通重启不得清空映射后重新分配相同地址给另一域名。映射丢失、损坏或不兼容时进入 Error，提示用户重启受影响应用并重新解析，再显式重建映射；恢复前拒绝无法关联的旧 FakeIP，不把它当真实 IP 外发或猜测域名。直连期间不维持隐藏 TUN；磁盘映射只用于后续兼容恢复，不能解决已停止内核后的应用缓存。M0 验证所选内核缓存和拒绝未知映射的能力，不满足时先调整方案。

### D5. 故障边界与后续增强

MVP 保证内核正常运行时，上游不可达、认证失败或协议不支持不会触发直连 fallback。内核或宿主崩溃、TUN 停止以及恢复过程中，不提供系统级零直连保证；不安装 WFP 持久阻断规则。内核退出时界面进入 Error，提示代理接管已失效、流量可能直连，不自动把最后成功模式写为 Direct；提供重新启用和显式直连恢复入口。

下次启动清理本程序残留路由/DNS 后再尝试恢复最后成功模式，期间展示恢复中及上述能力边界；恢复失败保持 Error，不能报告代理运行成功。正常退出的网络清理不改写最后成功模式，只有用户显式切换模式或成功应用配置才更新该模式。

后续独立增强提案候选：系统级崩溃阻断保护（不属于本 change 的任务或验收门槛，尚未单独立项）。该提案应验证 Windows 过滤机制，并要求恢复到代理模式时持续保留保护，先修复路由/DNS、启动内核并确认就绪，再交接保护，禁止“清除全部保护后重启内核”；显式直连或正常退出才解除保护。必须覆盖宿主崩溃、恢复失败、离线解除和阻断范围，另行确定可用性取舍。

### D6. 凭据与日志

采用用户范围 Windows DPAPI 或 Credential Manager，凭据引用与配置分离；M0 验证提升后的账户上下文，特别是标准用户输入另一管理员账户时不冒认原用户。若需临时内核配置含密码，文件限当前有效账户及必要系统身份访问，禁止放命令行参数和日志，退出清除并在下次启动清理残留；磁盘受限临时配置不是普通导出配置。

凭据采用不可变版本引用：编辑用户名/密码时写入新的受保护记录，不覆盖旧 credential_ref。应用当前代理的修改时，将旧配置修订及凭据引用保留在事务恢复记录；新内核配置就绪且配置原子提交成功才算提交。凭据写入、内核应用或配置持久化失败均恢复旧引用及旧运行配置，回滚失败保留可恢复记录并进入 Error。直连或非当前代理的编辑以配置持久化成功为提交点，不暗示认证已验证。此处应用成功指本地配置与内核就绪，不保证上游密码正确；运行后发现认证失败遵循连接失败语义，不自动撤回已提交编辑。

事务记录不含明文秘密；崩溃启动时以已持久化提交修订判定提交前/后状态并恢复对应配置和凭据引用。垃圾回收只删除不被已提交配置、运行快照、保留的备份或未完成事务引用的凭据；保留备份淘汰后才释放对应凭据，避免回滚指向已删除秘密。

从内核事件或经验证的管理接口提取连接结果及匹配规则，M0 核对是否能提供精确 rule id；无法取得时标注未知，不能使用应用模型重新猜测实际命中。日志在进入 UI/磁盘前脱敏，默认 20 MiB/7 天轮转，支持清空，不记录通信正文。

### D7. 界面与交付

五个功能页面是信息架构；暂定左侧导航、右侧内容、底部状态条，具体外观等待后续设计评审。规则编辑包含目标类型、目标、端口、名称、开关和备注；首页展示已应用模式、代理及错误。托盘左键显示/隐藏；右键单选模式和代理，并提供页面与退出入口。

打包为 Windows 安装程序并创建开始菜单入口，默认不注册开机启动。先锁定 Rust、内核与依赖版本，核对 sing-box、TUN 组件及分发许可证，包含所需声明与源代码提供义务（如适用）；安装器类型在构建阶段确定。

## Risks / Trade-offs

- DNS/FakeIP 与浏览器加密 DNS、缓存不一致 → 明确受支持路径，覆盖 SSH 无域名嗅探场景及 IPv6，显示识别限制。
- 内核崩溃可能恢复系统直连、残留网络设置可能断网 → 明确 MVP 不提供系统级阻断，验证 Error 提示、显式直连、幂等恢复及离线操作说明。
- 修改网络与 VPN 冲突 → 按所有权恢复；在当前可用实机环境以 Wi-Fi 断开/重连和 VPN 共存验证网络变化后的恢复。Wi-Fi/有线漫游需要两种物理网络同时可用，当前环境不具备时须明确记录为未验证，不得据此宣称有线切换已通过。
- 内核更新导致配置或日志接口变化 → 锁定版本，通过适配层升级并重跑契约测试。
- 代理切换需要重启 → 明示可能断开 SSH；仅将新连接切换作为可保证语义。
- 提权改变凭据账户上下文 → 在支持的用户/管理员组合验证配置目录、凭据和安装范围。
- macOS 无法验证 Windows 网络行为 → 发布必须附 Windows 10/11 实机或 VM 测试证据。

## Migration Plan

这是新项目，无旧数据迁移。按 tasks.md 的 M0 技术门槛 → 模型 → 内核 → 界面 → 交付推进。每步保持功能开关默认直连；在 Windows 验收完成前不宣称可发布。

未来配置版本升级先备份后转换，失败继续使用旧有效配置。安装升级/卸载前停止内核并恢复网络；不能把卸载当作恢复失败的替代。完成验收后再归档 change，将增量合并到 openspec/specs。

## Open Questions

不影响能力范围的待定细节：主窗口尺寸/配色/导航最终视觉稿、产品显示名和图标、安装器格式。sing-box 具体版本和接口由 M0 验证后记录；若验证改变本设计行为契约，须更新提案而非静默放宽验收。

## Approved Cache Patch

2026-09-20 用户批准按推荐方案维护最小内核补丁。上游固定 v1.14.1 / 1ac1a339cb1223e9c70eae14c44411c75033c02d；补丁、构建脚本和对应源码材料位于 third_party/sing-box。

新增 cache_file.strict_mode，默认关闭保留上游兼容行为，本应用生成配置必须开启。已有缓存先只读验证，空文件、格式错误、校验错误和不兼容版本均启动失败并保留文件。不存在文件允许首次创建；“以前初始化过但文件丢失”由 Rust 持久化初始化标记检测，不能仅凭内核区别首次使用。

运行期数据库恢复分支在严格模式下输出固定 STRICT_CACHE_ERROR 并立即以 78 退出，不删除或重建缓存，不继续分配地址。该退出属于 fail-stop，不执行内核优雅关闭；Windows 网络清理由 Rust 监管器负责，遵循 MVP 无系统级零直连保证的边界。启动失败可能使用 CLI 通用非零退出码，监管器同时检查错误标记，不能仅识别 78。

用户显式重建之前，控制器必须停止内核，保留隔离的旧文件及恢复记录，提示重新解析/重启受影响应用。补丁只解决已检测的数据库结构损坏自动重置，不声称可检测任意逻辑内容篡改、内核内存故障或全部掉电写入窗口。

Windows 构建采用带本项目后缀的版本号，保持上游源码、补丁、Go 模块锁定文件及构建选项可追溯；所有发行需附对应源码与许可证材料。替换内核后重跑认证、DNS、TUN、缓存与清理回归，不能沿用官方二进制的全部测试结论。
