## Context

参见 `proposal.md`。当前运行时将模式、当前代理和规则共同纳入运行键，因此规则代理与全局代理间的每次变化均走完整重启。Windows 实机验证已确认锁定的 `sing-box 1.14.1-socks-proxy.2` 支持由仅监听回环地址的 Clash API 在同一 PID 内完成 `Rule -> Global -> Direct -> Rule` 更新。全局直连和退出的 DNS 刷新仍是 FakeIP 网络恢复契约的一部分。

## Goals / Non-Goals

**Goals:**

- 让切换期间的 UI 和托盘持续响应，并将目标、阶段与最终实际状态严格分离。
- 将可失败的配置准备移到断开前，缩短不必要的网络中断窗口。
- 让规则与全局模式的常规切换在同一内核和 TUN 内完成，失败时保持既有网络接管而不回退重启。
- 在 Windows x64 真实桌面会话建立可重复的耗时基线和验收证据。

**Non-Goals:**

- 本变更不承诺现有连接、SSH 或所有 TCP 会话在内核切换中不断开。
- 不在模式控件或状态页展示静态 SSH 中断预警文案。
- 不改变路由规则、代理协议、凭据存储或 DNS/FakeIP 正确性边界。
- 不以异步返回代替全局直连和退出所需的网络恢复完成语义。

## Decisions

### D1. 用显式切换作业统一阶段、互斥和提交

控制器拥有单个后台模式切换作业。作业发出阶段事件并在完成通道返回事务结果；UI 只读取本地作业状态和最后快照，不能在作业期间再次调用会改变运行配置的控制器接口。最终状态仍由事务成功提交或回滚后的运行时快照确定。

选择作业状态机而非在每帧尝试加锁，是为了避免 UI 被互斥锁阻塞，并使托盘与窗口可共享同一关联标识。保留当前控制器的单一事务所有者而非并发运行多个运行时，避免 TUN、路由和持久化竞争。

### D2. 预检结果可复用且在停止前完成

为非直连目标模式引入仅含编译产物、受限配置文件和路由规则标识的预检产物。预检完成凭据读取、DNS 上游解析、配置编译、写盘和 `sing-box check`，只有成功后才允许停止当前运行内核；启动阶段消费同一产物，避免重复解析和写盘。预检产物不得保留明文凭据，也不得写入诊断日志。

选择复用预检产物而非只调整调用顺序，是为了同时减少中断前工作和重复成本。若预检产物失效或启动拒绝它，事务按既有回滚策略处理。

### D3. 规则与全局模式使用本机 API 热切换

编译的非直连配置同时声明 Rule、Global 和 Direct 路由分支，并启用仅监听 `127.0.0.1` 的本机控制接口。规则代理与全局代理的切换通过受认证的 `PATCH /configs` 更新模式，再读取当前模式确认；接口密钥在每次内核启动时随机生成，仅保留在内存和受限运行配置中，日志及诊断中一律脱敏。成功后提交新实际模式和持久化配置；更新或确认失败时不停止内核、不删除 TUN、不改写实际模式或持久模式。

选择该路径是因为 Windows 实机已验证固定内核在同一 PID 中提供 Rule、Global、Direct 模式更新，且规则项会读取运行时模式。每次完整重启虽可作为旧实现的后备，但会违反本次性能要求；热切换错误保持当前内核比强制重启更能维护连续接管。

### D4. 阶段遥测采用单调时钟和脱敏摘要

每次切换以关联标识聚合阶段事件，耗时用单调时钟计算，输出仅包含模式、阶段、结果、毫秒数、错误类别和脱敏错误摘要。成功记录保留最近有限数量，失败记录进入已有可读错误/日志入口；不记录密码、URL 用户信息、原始配置或完整内核输出。

这使性能基线可比较且不受系统时钟变化影响。仅记录总时长无法判断优化是否作用于 TUN、DNS 或内核就绪。

### D5. Windows 后台命令与轻量进行中反馈

Windows 下所有模式切换相关子进程使用同一 `CREATE_NO_WINDOW` 命令构造器，包括配置预检的 `sing-box check`、内核启动、TUN 清理和 DNS 刷新，避免预检遗漏而短暂显示控制台。状态页继续以实际已应用模式作为选中态，并在作业运行时禁用模式控件；不渲染操作 ID 或“正在应用配置”横幅。全局阶段状态和托盘进行中提示继续承担非阻塞反馈，失败仍显示可读错误。

## Risks / Trade-offs

- [预检写入的配置文件可能在切换取消或失败后残留] → 使用受限临时文件、作业结束清理和启动时残留清理，不持久化秘密。
- [本机控制接口被非应用进程调用] → 只监听回环地址，为每次内核启动生成随机密钥，并不记录或暴露该密钥。
- [后台任务持锁导致状态读取阻塞] → UI 渲染作业快照，运行时轮询和托盘刷新采用无阻塞状态副本。
- [直连路径被误优化而跳过 DNS 刷新] → 将 DNS 刷新锁定为直连/退出的必经阶段，并以故障注入验证错误可见与可重试。
- [热切换行为随 sing-box 版本变化] → 固定并在启动时校验支持该 API/模式的内核版本；不兼容时拒绝启用代理模式并报告版本错误，而不回退重启切换。

## Migration Plan

先加入阶段模型、预检和后台作业的确定性单元/控制器测试，再实现受认证的本机 API 热切换。Windows x64 release 在有效 SOCKS5/HTTP fixture 上采集优化前后规则、全局和直连切换的阶段耗时，验证同 PID、TUN/DNS 连续性、无效配置、接口认证失败、接口超时、内核启动失败、DNS 刷新失败和托盘重复点击。发布前以安装升级覆盖已有配置；回滚版本会重新采用完整重启，配置和凭据格式无需迁移。
