## Purpose

定义浏览器、SSH 与其他端口连接的三种流量模式，以及域名、IP 和端口规则的可观察语义，保证用户能够预测每条连接走当前代理还是直接连接。

## Requirements

### Requirement: 三种代理模式

程序 SHALL 仅提供规则代理、全局代理、全局直连。规则模式命中任意启用规则走当前代理，否则直连；全局模式所有可代理流量走代理但本机及局域网默认直连；直连模式停止接管。

#### Scenario: 规则命中和未命中
- **WHEN** 规则仅包含 203.0.113.10 的 22 端口
- **THEN** 该目标的 22 走代理，443 直连。

#### Scenario: 全局模式
- **WHEN** 全局代理下访问公网目标和局域网目标
- **THEN** 公网 TCP 使用当前代理，局域网默认直连。

#### Scenario: 全局直连
- **WHEN** 用户选择全局直连
- **THEN** 停止 TUN 接管并恢复网络，同时保留代理选择和规则。

### Requirement: 五种目标规则

程序 SHALL 支持精确域名、域名及子域名、单个 IPv4/IPv6、CIDR 及包含端点的 IP 范围；规则包含名称、启用开关和备注。无效输入 SHALL 拒绝保存。

#### Scenario: 域名边界
- **WHEN** 精确规则为 example.com，另一个测试使用域名及子域名规则
- **THEN** 精确规则只匹配自身；后者匹配自身及 a.example.com，但不匹配 badexample.com。

#### Scenario: IP 边界
- **WHEN** 规则为 192.0.2.10–192.0.2.30
- **THEN** 两个端点及中间地址命中，范围外地址不命中。

#### Scenario: IPv6 和网段
- **WHEN** 配置 IPv6 单地址及合法 IPv4/IPv6 CIDR
- **THEN** 按地址和前缀正确匹配，不依赖文本缩写形式。

#### Scenario: 非法范围
- **WHEN** 提交起点大于终点、混合地址族或非法 CIDR
- **THEN** 提示校验错误并保持原配置。

#### Scenario: 关闭规则
- **WHEN** 匹配目标的唯一规则被禁用
- **THEN** 规则模式下该目标直连。

### Requirement: 端口条件

程序 SHALL 支持空端口表示全部、单端口、多端口、范围及混合格式；同条规则目标与端口为 AND，多条规则为 OR。端口 SHALL 位于 1–65535，范围起点不得大于终点。

#### Scenario: 混合端口
- **WHEN** 规则端口为 22,443,8000-9000
- **THEN** 命中目标的 22、443、8000、9000 走代理，9001 不因该规则走代理。

#### Scenario: 端口留空
- **WHEN** 目标规则端口留空
- **THEN** 命中目标的全部支持端口走代理。

#### Scenario: 非法端口
- **WHEN** 输入 0、65536 或 9000-8000
- **THEN** 拒绝保存并解释错误。

### Requirement: 内网规则和基础例外

规则模式 SHALL 允许显式规则代理远程内网 IP；防止代理服务器自身连接回环以及本机控制通信被接管的基础例外 SHALL 优先于用户规则。

#### Scenario: 远程内网 SSH
- **WHEN** 规则指定远程内网 10.20.30.40:22，且非本机或代理服务器端点
- **THEN** 该连接走当前代理，不被笼统私网直连覆盖。

#### Scenario: 代理自身
- **WHEN** 代理地址落入用户 IP 规则
- **THEN** 建立上游代理连接时直接到达代理服务器，不形成回环。

### Requirement: DNS 与域名识别

程序 SHALL 在受管理 DNS 路径下使域名规则对浏览器和 SSH 的新连接生效，包括解析后只持有 IP 的连接；不得将未知域名伪报为已匹配。

#### Scenario: SSH 域名
- **WHEN** SSH 经程序管理的 DNS 解析命中域名规则的主机并连接指定端口
- **THEN** 连接走当前代理，日志可关联原始域名。

#### Scenario: 不可见域名
- **WHEN** 应用使用自有加密 DNS 或已有缓存且程序无法恢复域名
- **THEN** 仅按可获得的 IP/端口和模式决策，界面说明域名识别限制，不伪造命中信息。

### Requirement: 故障及传输能力边界

内核正常运行并接管流量时，应代理连接 SHALL 在上游不可达或协议不支持时失败，不自动直连；首版 SHALL 验收 TCP 浏览器与 SSH。HTTP 代理不支持的 UDP SHALL 明确失败；SOCKS5 UDP 仅在内核和服务端支持时启用。

#### Scenario: 上游故障
- **WHEN** 内核正常运行、当前代理不可达，直连网络及所需 DNS 可用，而规则模式同时有命中和未命中的连接
- **THEN** 命中连接失败，未命中连接继续正常直连。

#### Scenario: HTTP 的 UDP
- **WHEN** 应代理的 UDP 连接选中 HTTP 代理
- **THEN** 明确记录不支持，不以直连绕过；浏览器自行发起 TCP 回退时 TCP 仍遵循相同规则。

### Requirement: 合成地址与真实 IP 规则

程序 SHALL 将合成地址还原为域名后决策，不把合成地址用于用户真实 IP、CIDR 或 IP 范围匹配。基础例外之后，域名和端口规则命中即代理；否则存在 IP 类规则时 SHALL 解析真实 A/AAAA 候选地址，任一候选与端口命中即代理整条逻辑连接，全部未命中才直连。需要解析才能判定但解析失败时 SHALL 使连接失败，不回退直连。

#### Scenario: 域名访问命中 CIDR
- **WHEN** 仅配置 203.0.113.0/24:443 走代理，浏览器访问的域名真实解析为 203.0.113.10，应用获得合成地址
- **THEN** 443 连接走代理，合成地址不导致漏匹配；单 IP 和 IP 范围采用相同规则。

#### Scenario: 多地址解析
- **WHEN** 域名未命中域名规则，A/AAAA 候选集中仅一个真实地址命中启用的 IP 与端口条件
- **THEN** 整条逻辑连接使用当前代理，候选地址重试不切换为直连。

#### Scenario: 解析失败
- **WHEN** 域名未命中域名规则且需真实 IP 判定，但真实地址解析失败
- **THEN** 连接失败并记录解析错误，不视为规则未命中而直连。

#### Scenario: 全局模式下的域名内网例外
- **WHEN** 全局模式下访问通过受管理 DNS 解析的域名
- **THEN** 仅当真实候选全部为内网地址时适用内网直连例外；公网与内网混合候选使用代理，合成地址不参与此判定。

### Requirement: DNS 出站隔离

程序 SHALL 让启动引导、代理服务器地址、路由判定和未命中规则目标的 DNS 解析通过独立直连路径完成，使用接管前有效的网络 DNS 上游，不递归进入本程序监听入口，不依赖当前代理。已命中域名代理规则的目标 SHALL 使用代理端解析或经当前代理传输的 DNS，不在代理失败时回退直连解析。界面说明 SHALL 明示路由判定 DNS 属于直连例外、可能向本地 DNS 暴露查询，全局模式亦不承诺全部 DNS 经代理。

#### Scenario: 上游代理故障但普通域名可访问
- **WHEN** 当前代理不可达，直连 DNS 和网络可用，应用访问未命中域名及 IP 规则的目标
- **THEN** 解析独立完成且连接直连；命中代理规则的连接仍失败。

#### Scenario: 直连 DNS 故障
- **WHEN** 需要直连 DNS 完成路由判定或目标解析，但该 DNS 不可用
- **THEN** 连接失败并记录 DNS 错误，不以代理 DNS 重试来改变分流结果，也不宣称未命中流量必然可用。

#### Scenario: 已命中域名规则但代理解析失败
- **WHEN** 域名规则已确定代理出站，而代理端解析或经代理的 DNS 失败
- **THEN** 连接失败，不改用直连 DNS 解析该目标。
