## MODIFIED Requirements

### Requirement: 应用配置事务

程序 SHALL 在验证配置并确认内核就绪后才报告代理已启用；失败 SHALL 回滚至上一有效配置并报告实际状态。用户切换代理模式时，即使需要重启内核也 SHALL 直接开始事务，不要求额外手动确认；程序 SHALL 保持现有连接可能中断的可见说明。

#### Scenario: 配置校验失败
- **WHEN** 新规则导致内核校验失败
- **THEN** 保留旧运行配置和模式，显示错误，不保存为成功应用模式。

#### Scenario: 内核启动失败
- **WHEN** 内核文件缺失、版本不兼容或 TUN 创建失败
- **THEN** 不显示运行成功，清理本次修改并显示恢复结果。

#### Scenario: 切换中的 SSH
- **WHEN** 用户选择另一个代理模式且该切换需要重启或停止 TUN
- **THEN** 程序不弹出确认框而立即执行切换，界面预先提供现有 SSH 等连接可能中断的说明；切换只保证新连接使用新路径，不承诺现有 SSH 永不中断。

#### Scenario: 免确认切换失败
- **WHEN** 无确认模式切换在内核重启、配置应用或持久化阶段失败
- **THEN** 程序按原事务规则回滚并显示实际有效模式和错误，不因取消确认步骤而绕过校验或虚报成功。
