## Why

当前主窗口虽然已经覆盖状态、代理、规则、日志和设置五个页面，但视觉层级、内容密度、控件一致性和操作反馈较弱，用户难以快速判断网络是否被接管、当前使用哪个代理，以及操作是否正在执行或已经失败。需要在不更换 Rust + egui 技术栈、不改变代理语义的前提下，建立适合长期使用的紧凑 Windows 桌面工具界面。

## What Changes

- 重构主窗口的信息架构和视觉系统，统一字体层级、颜色、间距、图标、按钮、表格、表单、提示和空状态。
- 将全局运行状态、当前模式、当前代理和异常集中到稳定可见的位置，并为应用中、退出中、成功、失败和重试提供一致反馈。
- 重做五个页面：状态页突出常用控制与最近活动；代理和规则页采用紧凑、可扫描的管理列表；日志页提供筛选与完整详情；设置页按功能分组。
- 改善最小窗口、长文本、键盘焦点、禁用态和高对比度下的可读性，不让内容重叠或关键操作移出可见区域。
- 保持原生 Rust 桌面交付，不引入 HTML、CSS、JavaScript 或 WebView；托盘菜单继续使用系统原生样式，只统一其命令结果与主窗口反馈。
- 将界面拆分为主题、通用组件和页面模块，降低后续功能修改的界面维护成本。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `desktop-shell`：将待确认的主窗口布局升级为明确的紧凑信息架构、统一视觉与交互反馈，并规定五页管理体验、响应式边界和可用性验收。

## Impact

主要影响 `src/ui/mod.rs`，并会拆分出主题、组件和页面模块；可能引入与 egui 兼容的图标字体或内嵌资源，但不改变 UI 框架、控制器接口、配置格式、托盘协议或代理内核。需要更新 UI 状态测试、Windows 10/11 实机截图与交互验收、用户指南和现有布局验证文档。为减少冲突，本变更应在 `improve-mode-logs-tray-ux` 的功能行为完成后实施，并复用其日志详情和退出状态机。
