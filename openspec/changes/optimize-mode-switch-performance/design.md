## Context

参见 `proposal.md`。当前运行时将模式、当前代理和规则共同纳入运行键，因此规则代理与全局代理间的每次变化均走完整重启。配置编译发生在停止当前后；Windows 进程停止路径会清理使用过的 TUN，清理后包含固定等待。模式请求由 egui 更新线程同步持有控制器锁并等待事务完成。全局直连和退出的 DNS 刷新仍是 FakeIP 网络恢复契约的一部分。

## Goals / Non-Goals

**Goals:**

- 让切换期间的 UI 和托盘持续响应，并将目标、阶段与最终实际状态严格分离。
- 将可失败的配置准备移到断开前，缩短不必要的网络中断窗口。
- 将规则与全局模式的常规切换从 TUN 删除/重建路径移开，同时保留有界失败恢复。
- 在 Windows x64 真实桌面会话建立可重复的耗时基线和验收证据。

**Non-Goals:**

- 本变更不承诺现有连接、SSH 或所有 TCP 会话在内核切换中不断开。
- 不改变路由规则、代理协议、凭据存储或 DNS/FakeIP 正确性边界。
- 不在缺少 Windows 网络安全验证时默认启用 sing-box 热重载。
- 不以异步返回代替全局直连和退出所需的网络恢复完成语义。

## Decisions

### D1. 用显式切换作业统一阶段、互斥和提交

控制器拥有单个后台模式切换作业。作业发出阶段事件并在完成通道返回事务结果；UI 只读取本地作业状态和最后快照，不能在作业期间再次调用会改变运行配置的控制器接口。最终状态仍由事务成功提交或回滚后的运行时快照确定。

选择作业状态机而非在每帧尝试加锁，是为了避免 UI 被互斥锁阻塞，并使托盘与窗口可共享同一关联标识。保留当前控制器的单一事务所有者而非并发运行多个运行时，避免 TUN、路由和持久化竞争。

### D2. 预检结果可复用且在停止前完成

为非直连目标模式引入仅含编译产物、受限配置文件和路由规则标识的预检产物。预检完成凭据读取、DNS 上游解析、配置编译、写盘和 `sing-box check`，只有成功后才允许停止当前运行内核；启动阶段消费同一产物，避免重复解析和写盘。预检产物不得保留明文凭据，也不得写入诊断日志。

选择复用预检产物而非只调整调用顺序，是为了同时减少中断前工作和重复成本。若预检产物失效或启动拒绝它，事务按既有回滚策略处理。

### D3. 将 TUN 清理分为模式过渡与最终恢复

规则代理与全局代理的正常过渡停止旧核心进程但保留本程序拥有的 TUN 适配器，并以短轮询、有总时限的状态检测确认旧进程资源已释放。仅切换直连、正常退出、异常恢复或复用失败时执行适配器删除、路由/DNS 恢复和 DNS 缓存刷新。任何有界等待超时均返回可见错误和恢复记录，不假定网络已恢复。

选择此分界是因为规则和全局模式都持续要求 TUN 接管。保留每次删除再重建最简单但造成固定等待和驱动初始化成本；直接去掉等待则可能与 Windows 设备释放竞争。

### D4. 热重载作为独立受控能力开关

设计预留内核后端的“可重载”能力，但初始实现仍使用预检后的受控重启。只有在真实 Windows 会话中证明规则/全局互切不会造成 DNS、路由或流量直连窗口，并且失败能回滚到上一个可用配置后，才可通过默认关闭的能力开关启用热重载。日志必须注明实际采用路径。

选择延后默认启用是因为 sing-box 的 API/重载行为、TUN 接管和 FakeIP 持久映射必须用目标版本验证。完整重启是已存在并可测试的后备路径。

### D5. 阶段遥测采用单调时钟和脱敏摘要

每次切换以关联标识聚合阶段事件，耗时用单调时钟计算，输出仅包含模式、阶段、结果、毫秒数、错误类别和脱敏错误摘要。成功记录保留最近有限数量，失败记录进入已有可读错误/日志入口；不记录密码、URL 用户信息、原始配置或完整内核输出。

这使性能基线可比较且不受系统时钟变化影响。仅记录总时长无法判断优化是否作用于 TUN、DNS 或内核就绪。

## Risks / Trade-offs

- [预检写入的配置文件可能在切换取消或失败后残留] → 使用受限临时文件、作业结束清理和启动时残留清理，不持久化秘密。
- [复用 TUN 时旧内核尚未释放设备] → 通过短间隔轮询和有界超时确认；失败走完整恢复或回滚并保留错误。
- [后台任务持锁导致状态读取阻塞] → UI 渲染作业快照，运行时轮询和托盘刷新采用无阻塞状态副本。
- [直连路径被误优化而跳过 DNS 刷新] → 将 DNS 刷新锁定为直连/退出的必经阶段，并以故障注入验证错误可见与可重试。
- [热重载行为随 sing-box 版本变化] → 默认关闭，使用版本固定的 Windows 测试和回退重启。

## Migration Plan

先加入阶段模型、预检和后台作业的确定性单元/控制器测试，再实现 TUN 复用与有界轮询。Windows x64 release 在有效 SOCKS5/HTTP fixture 上采集优化前后规则、全局和直连切换的阶段耗时，验证无效配置、内核启动失败、TUN 清理超时、DNS 刷新失败和托盘重复点击。发布前以安装升级覆盖已有配置；回滚版本继续以完整重启运行，配置和凭据格式无需迁移。
