## MODIFIED Requirements

### Requirement: 应用配置事务

程序 SHALL 在验证配置并确认内核就绪后才报告代理已启用；失败 SHALL 回滚至上一有效配置并报告实际状态。对于会替换有效运行配置的模式切换，程序 SHALL 在停止当前有效内核前完成目标配置的凭据读取、上游解析、配置生成和内核配置校验；预检失败 SHALL 保持当前已应用模式、内核和网络接管不变。规则代理与全局代理之间的切换 SHALL 通过当前运行内核的受认证本机控制接口完成，不得停止或重启内核、删除或重建受管 TUN 适配器；接口调用、模式确认或模式持久化失败 SHALL 保持此前实际模式、内核和网络接管，并显示可读错误。切换全局直连和正常退出 SHALL 继续完成本程序拥有的网络恢复及 Windows DNS 缓存刷新。

#### Scenario: 配置校验失败
- **WHEN** 新规则导致内核校验失败
- **THEN** 保留旧运行配置和模式，显示错误，不保存为成功应用模式。

#### Scenario: Windows 配置预检
- **WHEN** Windows 为非直连目标运行 `sing-box check`
- **THEN** 配置校验使用无控制台窗口的子进程创建方式，且不短暂显示命令行窗口。

#### Scenario: 内核启动失败
- **WHEN** 内核文件缺失、版本不兼容或 TUN 创建失败
- **THEN** 不显示运行成功，清理本次修改并显示恢复结果。

#### Scenario: 切换中的 SSH
- **WHEN** 用户切换代理或模式
- **THEN** 规则代理与全局代理热切换优先仅影响新连接；全局直连的网络恢复可能影响现有连接，但界面不展示静态 SSH 中断提示，且不承诺 SSH 永不中断。

#### Scenario: 模式预检失败
- **WHEN** 用户从正在运行的规则代理切换到无效的全局代理配置
- **THEN** 程序在停止旧内核前报告预检失败，规则代理保持已应用且网络接管连续。

#### Scenario: 规则与全局模式热切换
- **WHEN** 用户在有效规则代理和全局代理之间切换
- **THEN** 程序在同一内核进程和受管 TUN 适配器内完成路由模式更新，不删除或重建该适配器。

#### Scenario: 热切换失败
- **WHEN** 当前内核的本机控制接口拒绝、超时或无法确认目标代理模式
- **THEN** 程序不停止或重启内核，保持此前实际模式和网络接管，并显示失败阶段与可读错误。
