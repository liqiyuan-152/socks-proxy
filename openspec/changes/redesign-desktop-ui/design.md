## Context

当前桌面层基于 `eframe/egui 0.36.2`，五个页面、对话框、导航和样式集中在 `src/ui/mod.rs`。主窗口使用 176px 固定侧栏、右侧内容区和底部状态条，只有少量全局样式覆盖；代理和规则使用裸 `Grid`，日志使用固定宽度截断标签。业务操作已经经 `SharedController` 暴露，界面可以独立重构。参见 `proposal.md` 与 `specs/desktop-shell/spec.md`。

本变更与 `improve-mode-logs-tray-ux` 会触及相同 UI 文件；后者先建立日志详情、托盘反馈和异步退出行为，本变更再重构其表现，避免并行实现产生冲突。

## Goals / Non-Goals

**Goals:**

- 在不改变代理、路由、凭据和恢复语义的情况下重做整个主窗口。
- 建立可复用的设计令牌和组件，使五个页面看起来并表现为同一产品。
- 在默认尺寸、760×520 最小尺寸以及 Windows 100%/150% 缩放下保持高信息密度和可读性。
- 让运行状态、耗时操作、错误和恢复动作始终容易发现。
- 将 UI 代码拆分到清晰模块，降低后续功能变更成本。

**Non-Goals:**

- 不更换 egui/eframe，不引入 WebView、HTML、CSS 或 JavaScript。
- 不追求逐像素复刻 WinUI 3、Mica 材质或系统原生动画。
- 不自定义 Windows 托盘右键菜单的系统绘制样式。
- 不改变代理协议、规则匹配、DNS、回滚、凭据保护或备份格式。
- 不在本变更中增加流量统计、延迟测试、规则拖拽排序或多主题持久化。

## Decisions

### D1. 保留 egui，仅替换展示层

继续使用现有 eframe 窗口和 `SharedController`，页面只读取 `UiState` 并发送明确命令。状态、代理、规则、日志和设置页面可以完全重排，但不得绕过控制器直接修改配置或运行状态。

相比迁移 WinUI 3，这能保留纯 Rust 交付和现有测试边界，并将风险限制在 UI。代价是部分控件不会具备完全原生的 Windows 外观，系统材质与动画不在范围内。

### D2. 建立令牌、组件、页面三层结构

将 UI 拆分为 `theme`、`components` 和 `pages` 三层：主题集中定义字体、颜色、间距、圆角、描边和状态色；组件提供页面标题、分段控件、状态标记、工具栏、数据行、空状态、错误横幅和表单行；各页面只组合组件并调用现有动作。

图标采用本地打包的 Lucide 资源并记录许可证，不在运行时联网。图标只用于熟悉命令和状态，所有不熟悉的图标按钮提供悬停说明和可访问名称；删除等危险命令同时保留文字或确认上下文。

### D3. 使用稳定应用框架和两档响应式导航

窗口保持左侧导航、中央工作区和稳定状态区。常规宽度使用约 176px 的图标加文字导航；宽度不足时收缩为固定宽度图标栏，通过工具提示显示名称，不改变页面顺序。页面标题区承载标题、简短副标题和右侧主要操作；全局运行状态固定显示，不随页面滚动消失。

默认窗口目标调整为约 1000×680，仍支持 760×520 最小尺寸。固定格式控件使用明确的最小/最大宽度、行高和滚动区；不按视口连续缩放字体，避免布局抖动。

### D4. 采用克制的浅色工作台视觉

首版使用单一浅色主题：中性灰背景、白色或近白工作区、蓝色交互强调，以及独立的绿色成功、琥珀警告和红色错误。颜色只用于强化文字和图标表达，不作为唯一状态通道。页面区域采用分隔线和留白组织，不将整页或每个小字段包装成浮动卡片。

不在本次加入深色主题，是因为主题持久化和所有状态对比度会扩大测试矩阵；令牌结构为后续主题保留扩展点。

### D5. 管理列表采用摘要行和上下文详情

代理和规则列表使用固定行高、稳定列约束与行级操作。规则筛选只作用于当前内存视图，不修改顺序或配置。日志保留紧凑摘要，通过详情区域呈现长文本；筛选条件同样只作用于已加载且已脱敏的 `ConnectionEvent`，不读取原始内核日志。

在 760px 宽度无法容纳全部列时，保留名称、状态和主要操作，其余字段进入可展开详情或水平滚动区。任何被省略的文本都必须能在详情或提示中完整读取。

### D6. 操作反馈由页面状态模型统一驱动

页面组件消费现有运行快照，并增加纯 UI 状态：筛选文本、当前展开行、焦点目标和局部提交状态。由 `improve-mode-logs-tray-ux` 提供的应用中、退出中和错误结果映射到统一状态横幅与控件禁用规则；UI 状态不得伪造控制器成功。

错误横幅保持到用户关闭、重试成功或相关上下文改变。成功反馈可以短暂显示，但真实状态必须持续反映在全局状态区。退出期间只渲染本地退出进度并轮询结果，不等待控制器锁。

### D7. 以确定性布局检查和 Windows 实机截图共同验收

组件测试验证响应式断点、筛选、展开、空状态、焦点和禁用规则；Windows 10/11 实机在默认尺寸和最小尺寸、100% 与 150% 缩放下逐页检查。验收截图必须覆盖正常、空、应用中、长文本、错误和退出中状态，并确认没有遮挡、裁切、低对比度或不可达操作。

DNS、运行事务、网络回滚和 DPAPI 凭据处理继续沿用既有测试；界面重构不得降低这些门禁。日志截图只使用脱敏样本，代理密码不得进入 UI 快照或测试证据。

## Risks / Trade-offs

- [egui 与 Windows 原生控件观感仍有差异] → 使用一致令牌、Lucide 图标和克制布局建立产品感，不模拟无法稳定复现的系统材质。
- [UI 拆分与功能修复同时修改 `src/ui/mod.rs`] → 先完成并验证 `improve-mode-logs-tray-ux`，再基于其最终状态拆分模块。
- [紧凑列表在最小窗口中列宽不足] → 明确定义优先列、详情入口和滚动边界，禁止无出口的永久截断。
- [图标字体加载失败导致按钮不可理解] → 保留可访问名称与工具提示，启动时验证资源并为关键命令提供文字回退。
- [筛选和展开状态增加界面复杂度] → 只保存当前会话的轻量 UI 状态，记录删除或日志清空时同步清理失效选择。
- [高 DPI 与中文字体度量在设备间不同] → 使用 Windows 实机的 100%/150% 验收和稳定尺寸约束，不依赖单个平台截图。

## Migration Plan

1. 先完成并验证 `improve-mode-logs-tray-ux`，锁定日志详情、托盘反馈和退出状态模型。
2. 引入主题与通用组件，在不改变控制器行为的情况下逐页迁移；每迁移一页即运行现有控制器和 UI 测试。
3. 完成响应式导航、筛选与状态反馈后，在 Windows 10/11 执行默认/最小尺寸及 DPI 验收。
4. 更新用户指南和截图，重新构建安装包并执行升级安装、网络恢复和卸载回归。
5. 如需回滚，恢复旧页面组合层；控制器、配置、网络恢复记录和凭据格式均保持兼容。
