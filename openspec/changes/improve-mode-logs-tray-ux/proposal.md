## Why

当前模式切换会在内核需要重启时额外要求用户确认，首次启动又落在全局直连；连接日志的固定宽度截断使关键结果不可读，部分托盘菜单操作也可能没有可观察结果。这些行为增加了日常切换成本，并让故障诊断和托盘操作缺乏确定性。

## What Changes

- 切换代理模式时直接执行所需的内核重启，不再弹出手动确认；仍保持事务、失败回滚和真实状态反馈。
- 连接日志提供完整详情查看能力，使目标、出站、规则、结果和错误文本均可读取，同时继续在展示前脱敏。
- **BREAKING**：无本地配置的首次启动默认模式由全局直连改为规则代理；没有可用代理时保持明确的未运行/待配置状态，不虚报代理已启用。
- 修复托盘右键菜单交互，确保每个可操作菜单项要么完成对应动作，要么展示明确错误；页面入口会显示并聚焦主窗口。
- 优化托盘退出流程：立即展示退出进度，在后台停止内核并恢复网络，为外部清理命令设置超时；成功后关闭，失败时保留可重试界面。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `configuration-storage`：首次启动的默认期望模式改为规则代理，并明确缺少代理配置时的状态。
- `core-lifecycle`：用户切换代理模式时不再要求重启确认，同时保留切换事务和断连边界。
- `connection-logs`：连接日志必须提供不被截断丢失的完整详情查看方式。
- `desktop-shell`：托盘菜单的模式、代理、页面和退出操作必须有确定且可观察的结果，退出清理期间界面保持响应并展示进度。

## Impact

主要影响 `src/storage/mod.rs` 的默认配置、`src/core/transaction.rs` 与 `src/ui/controller.rs` 的切换及异步退出接口、`src/core/process.rs` 与 `src/core/runtime.rs` 的有界清理、`src/ui/mod.rs` 的模式交互和日志/退出状态展示，以及 `src/ui/tray.rs` 的菜单事件处理。需要更新相关 Rust 单元/集成测试、Windows 托盘与启动验证脚本、用户指南和验收记录；不新增依赖，不改变代理协议、规则匹配语义或凭据存储格式。
