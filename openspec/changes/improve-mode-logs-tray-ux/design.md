## Context

现有应用把所有可能触发内核重启的操作统一建模为 `restart_confirmed`，模式按钮和托盘模式项第一次调用时会得到确认错误，再由通用弹窗二次提交。连接日志页面把五列都固定为 132px 并调用截断；日志适配器启动时读取全部 JSONL、状态读取时克隆全部事件、每条完成事件又重写整个保留文件。托盘菜单通过全局事件接收器映射命令，但测试主要验证菜单存在与少量最终状态，没有系统锁定每个启用项的可观察结果。托盘退出当前在 UI 更新线程同步停止子进程、调用 PowerShell/`pnputil` 删除 TUN、固定等待 500ms 并运行 `ipconfig /flushdns`，外部命令没有超时，清理完成前无法刷新界面。默认配置当前将 `last_applied_mode` 设为全局直连。

本变更仍遵循既有事务、网络所有权恢复、凭据保护和 Windows-only 实机验收约束。参见 `proposal.md` 和四份 delta spec。

## Goals / Non-Goals

**Goals:**

- 将模式选择变成单次操作，同时保留验证、重启、提交和回滚的原子性。
- 为首次无配置状态建立“期望规则代理、实际未接管、等待代理配置”的一致模型。
- 让日志摘要保持可扫描，并为每条记录提供完整脱敏详情。
- 让日志在历史量接近保留上限时仍可快速打开、筛选、翻页和持续写入。
- 去除所有成功提示，保留进行中与错误反馈，避免底部成功信息干扰操作界面。
- 对托盘命令建立统一的动作、窗口聚焦、错误反馈和 Windows 自动化覆盖。
- 将耗时退出清理移出 UI 更新线程，提供进度、去重、超时和失败重试。

**Non-Goals:**

- 不取消编辑当前代理、切换当前代理或修改运行中规则时已有的中断确认策略。
- 不承诺内核重启期间保留现有 SSH，也不加入系统级流量阻断。
- 不改变日志采集字段、7 天/20 MiB 保留策略或脱敏规则。
- 不新增托盘菜单项、后台服务、通知中心或 Web UI。
- 不以立即终止应用替代内核停止、网络所有权恢复或 DNS 缓存刷新。

## Decisions

### D1. 模式切换在控制器边界自动授权重启

模式切换入口不再向 UI 暴露确认参数，控制器针对明确的模式选择直接允许 `Restart` 计划继续执行。底层切换事务继续保留计划、校验、应用、持久化和回滚阶段，供其他会修改有效配置的操作继续使用确认策略。

选择这一边界而不是删除全部确认机制，是为了精确满足模式切换免确认，同时不意外改变代理编辑和规则编辑的中断风险。UI 删除模式对应的待确认动作与弹窗路径，并在模式控件附近保留静态断连说明。

### D2. 首次默认规则代理使用期望态与实际态分离

新配置的持久默认值改为 `Rules`。启动恢复检测到 Rules/Global 但不存在有效当前代理时，不尝试启动内核，也不进入虚假的 Running；快照保留 `desired_mode=Rules`、`applied_mode=Direct`，界面显示待配置状态。保存首个有效当前代理后，现有控制器按期望模式应用配置。

不创建内置代理或占位凭据，避免引入无效秘密和不可预测网络行为。现有配置继续按其已保存模式恢复，不做 schema 迁移或强制改写。

### D3. 日志使用摘要行加完整详情

日志列表继续按新到旧展示紧凑摘要。每条记录提供可点击或可展开的详情区域，以标签和值展示完整时间、目标、端口、出站、规则和结果；长文本自动换行并允许选择复制。详情只使用已经过日志适配器脱敏的 `ConnectionEvent`，不回读原始内核行。

相比简单取消截断并无限扩宽表格，详情视图能在 760px 最小窗口中保持可读，也不会让一条长错误破坏整张列表布局。

### D3.1 日志采用游标分页、增量写入和虚拟行

日志存储以追加写入承载新事件，并维护有限的内存最新窗口和可从文件尾部向前读取的稳定游标。首次日志页请求只返回最新固定页；继续加载和筛选按游标读取固定上限的更早匹配记录。UI 使用虚拟滚动，只构建可见摘要行，详情保留脱敏事件快照而不依赖整页重建。达到既有时间或容量限制时，后台轮转到新的受限日志段，避免每条事件重写完整历史。

该策略参考 Clash Verge 一类桌面代理工具的“持续流式日志加视口渲染”体验：新日志不会迫使全部历史参与布局，用户仍可逐页回溯。相比一次性将 20 MiB JSONL 全部解析到内存，游标分页将常规读取和渲染成本限制在页面与视口大小；相比引入数据库，它保留当前 JSONL 的可移植性和低部署复杂度。

### D3.2 成功仅由结果状态表达

删除全局成功消息状态和通用成功横幅调用。成功的保存、切换、导入、导出、清空和托盘操作由改变后的页面数据、选中项或窗口状态表达；后台作业继续显示进行中，失败继续展示完整错误。该规则适用于所有入口，避免模式切换后在主界面下方保留与当前操作无关的成功信息。

### D4. 托盘命令统一产生结果并接受逐项验证

保留现有稳定菜单 ID，将菜单事件解析成可独立测试的命令映射。页面命令总是设置页面、显示并聚焦窗口；模式和代理命令执行后同步状态，错误时显示并聚焦窗口；退出失败同样回到可见错误状态。选择当前已生效值可以是幂等操作，但菜单选中状态必须保持正确。

Windows 验收使用真实托盘逐项点击三种模式、代理、五个页面和退出路径，并记录窗口页面、焦点/可见性、运行状态或错误。单元测试覆盖菜单 ID 到命令的完整映射，防止新增或重建菜单时出现无处理项。

### D5. 退出使用单一后台清理状态机

托盘退出命令先把应用切换到 `Exiting` 状态，显示并聚焦主窗口、展示“正在退出”，禁用会改变网络状态的控件并忽略重复退出请求；随后在单一后台工作线程持有共享控制器锁并执行现有 `shutdown`。UI 通过通道轮询完成结果，成功后发送窗口关闭命令，失败后回到可操作状态并显示可重试错误。

内核进程等待、PowerShell/`pnputil` TUN 清理和 `ipconfig /flushdns` 使用有界命令执行。建议初始上限为内核停止 10 秒、TUN 清理 30 秒、DNS 刷新 10 秒；超时视为清理失败，终止受管命令进程树、保留恢复记录并返回 UI，绝不在未确认恢复完成时直接关闭应用。具体常量集中定义并由 Windows 故障注入测试锁定。

选择后台状态机而不是点击后立即隐藏或强退，是为了同时解决界面无响应和网络清理正确性。工作线程只执行一次退出事务，不并行调用模式切换或重复恢复；窗口关闭按钮在 Exiting 期间不能绕过该事务。

## Risks / Trade-offs

- [模式误触会立即重启内核并中断连接] → 在模式控件和用户指南持续显示断连说明，保持切换失败回滚。
- [默认 Rules 但尚无代理可能被误解为已启用] → 明确区分期望模式与实际模式，未配置时保持 Direct/未接管并显示待配置。
- [日志详情使页面状态更复杂] → 详情状态只保存当前记录标识或快照，不改变持久日志格式；记录被清空时同步关闭详情。
- [游标与筛选可能产生重复或遗漏] → 使用稳定记录标识和时间/偏移游标，单元测试覆盖连续写入、翻页、筛选变化、轮转和清空。
- [实时日志将列表滚动位置拉回顶部] → 用户不在最新位置时显示未读数而不自动跳转；仅位于最新位置时增量追加并保持跟随。
- [Windows Shell 事件或焦点行为因版本不同] → 在 Windows 10/11 真实桌面会话验证，不用仅构造菜单的单元测试替代。
- [托盘切换失败后窗口抢焦点] → 仅在用户主动点击托盘命令后显示窗口，后台状态刷新不主动抢焦点。
- [清理超时可能留下 TUN 或恢复记录] → 不关闭应用，明确显示失败步骤并保留幂等重试入口；下次启动继续执行残留恢复。
- [后台线程持有控制器锁时常规状态刷新阻塞] → Exiting 状态下 UI 不再请求控制器快照，只轮询结果通道并渲染本地进度状态。

## Migration Plan

发布前更新单元测试、Windows 10/11 托盘自动化与用户指南，重新构建安装包并完成升级安装验证；退出验收记录点击到进度可见、清理完成和总耗时，并注入超时验证重试路径。日志升级时保留现有 JSONL 并首次读取时建立或重建索引/段信息；索引异常时只重建索引，不丢弃可解析日志。已有用户配置保持原 `last_applied_mode`，只有首次无配置用户采用 Rules 默认值。若回滚版本，旧版可继续读取 JSONL；已保存的 Rules 值会按旧版恢复逻辑处理。
